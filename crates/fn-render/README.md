# fn-render

Pure-Rust renderer for the Fortnite 1.8 (UE 4.16) runtime on **wgpu** (Vulkan + DX12 only, no GL, no Win32, no C/C++ in the render path).

* `gpu` device/adapter setup + offscreen target with read-back; `camera` projection + `CameraUniform`; `lighting` recovered sun/sky/terrain constants and the 3-cascade, texel-snapped shadow fitting; `sky` dome/sun/clouds; `tonemap` UE 4.16 post constants and CPU mirrors; `graph` the small frame graph; `renderer` pipelines + frame description.
* Frame: 3 shadow cascades (2048^2 depth array, 5x5 hardware-compare PCF) -> sky (Rgba16Float HDR) -> scene (ground + GPU-skinned character parts, bone matrices in a storage buffer, UE height fog) -> HDR mip chain -> exposure compute -> post (AO, bloom, exposure, cos^4 vignette, white balance, ACES film curve, sRGB).
* Approximate/not ported: bloom kernels and AO are the prototype's approximations, no DOF/motion blur, no left-hand IK; fog = the exact UE 4.16 ExponentialHeightFog PS maths (`common.wgsl`, `fog.rs`) plus the GPU volumetric fog (`volfog.rs` / `volfog.wgsl`, composited after the opaque scene; translucent FX / particles get only the height-fog part), Triangle-filtered CPU mips like the prototype.

## Shaders / rust-gpu plan
All shader code is WGSL in `shaders/` (`common`, `scene`, `shadow`, `sky_*`, `post`, `downsample`, `meter`); the Rust side only concatenates files. Plan: later move shader crates to rust-gpu (SPIR-V, shared `#[repr(C)]` uniform structs from `camera.rs`/`tonemap.rs`/`renderer.rs`), keeping this directory as the single place for shader sources and the entry-point names/bind-group layout as the contract; wgpu accepts SPIR-V passthrough on Vulkan, DX12 needs a naga SPIR-V->HLSL step.

## Verification
`cargo test -p fn-render` (cascade fitting, camera uniforms, tonemap maths, sky helpers); `fn-viewer --screenshot` for images.


## Public API additions (additive; fn-app: read this)
* **One call per frame**: `Renderer::render_with_overlay(&FrameParams, &TextureView, Option<&mut dyn UiOverlay>) -> FrameStats`. Draws shadows, sky, scene, post chain (+FXAA) into the view, then lets the overlay draw into the SAME view (UI in sRGB space over the tone-mapped frame) and submits. `Renderer::render` is unchanged (= no overlay). `fn_render::UiOverlay` is the hook trait; `fn_ui_wgpu::UiPass { renderer, list, assets }` implements it, so: `renderer.render_with_overlay(&fp, &view, Some(&mut UiPass { renderer: &mut ui, list: &list, assets: &mut ctx.assets }))`. The swapchain format must be non-sRGB (`fn_ui_wgpu::pick_surface_format`); create `UiRenderer::with_device(device.clone(), queue.clone(), format)` from the same device/format as `Renderer::new`.
* `RenderOptions` gained fields (construct with `..Default::default()`): `fxaa: Option<FxaaParams>`, `backdrop: Backdrop` (pause-menu dim + blur of the finished scene, `Backdrop::PAUSE_MENU`; the UI menu is drawn by the overlay on top), `shadow_map_size` (re-creates the shadow array when it changes), `anisotropy`, `skip_mips` (sampler minimum LOD = old "Textures" quality). `fn_render::quality` holds the old settings tables (`shadow_map_size`, `far_plane_m`, `aa_params`, `texture_params`, `post_flags`, `display_exponent_for_brightness`). View distance = `CameraParams::far` (set it to `quality::far_plane_m(level)`; the sky keeps its own far plane).
* `Renderer::set_props(&[PropVertex])`: world-space triangle list (flat normals, linear vertex colour) for the procedural trees/rocks; they cast and receive shadows (also the character's shadow falls on them). Build the vertices from `fn_combat::{prop_mesh, prop_normal, prop_vertex}` exactly like `fn-viewer/src/props.rs` and call it whenever a prop shakes/appears.
* Debug/verification: `Renderer::read_hdr() -> HdrImage` (linear HDR target readback), `tonemap::display_transform` (CPU reference of the whole display transform), `Gpu::create_instance` honours `FN_VALIDATION=1|2|0` (API validation + stderr logger; 2 = GPU-based validation) and `WGPU_BACKEND`/`FN_BACKEND`.
* The pickaxe is a `ModelId` like the body/head (`MaterialKind::Prop`, attached to `weapon_r` by the caller; see `fn-viewer/src/scene.rs`).

## Brightness investigation (task log)
The 7 % gap reported earlier was NOT a shader bug any more: with props missing, the auto-exposure meter averaged a different scene (new 1.30 vs old 1.21 exposure) and the comparisons were done at unequal exposure. Stage-by-stage diff against the old runtime's own debug captures (`fn-viewer --stages`, exposure of each capture taken from `verification\post-smoke.txt`) shows: sky +0.1 % at every stage (exposure-linear, no-film-curve, final), vignette mask identical to the pixel, ground within +-1.3 %, GPU post chain vs the CPU reference of the old maths (`fn-viewer --verify-post`) max 1 level of 255. Idle capture (`verification\idle.bmp`, 1264x761, props + HUD, `--demo-ui`): full-frame luma 115.2 vs 114.5 (+0.6 %) with auto exposure; at the old runtime's effective exposure (1.37, new auto 1.386) every region (sky, ground, character, trees, rock, shadow, quickbar, vitals, minimap) is within +-0.5 %. Residual: the old exposure had not fully converged when idle.bmp was taken (adaptation lag), the new one snaps to the metered value; the old smoke captures have no character shadow (old runtime skipped the shadow pass without props), which is a quirk, not reproduced.
## Static props, per-pass GPU timing (task log, additive API)
* **Prop shading** has its own pipeline: `vs_prop` + `fs_prop` in `scene.wgsl`, bind group 0 only (no material / skinning). It is a port of the old runtime's untextured generic path of `color.frag` with the vertex colour as linear albedo: `albedo * (sun_radiance * max(n.l,0) * cascade visibility + sky_radiance * clamp(0.5+0.5 n.y,0,1))`, UE height fog, ambient share in HDR alpha so AO only touches ambient. Props cast (`shadow.wgsl vs_prop`) and receive the 3 cascades. NOTE for fn-app: the character/pickaxe material (`MaterialKind::Character/Prop`, skinned) is NOT meant for trees/rocks (it samples diffuse/normal/spec textures, so an untextured mesh through it goes dark); use `set_prop_instances` / `set_props`.
* **Prop API**: `Renderer::set_prop_instances(&[PropInstance])` with `PropInstance { kind: fn_combat::Kind::{Tree,Rock}, pos, yaw (rad, about Y), scale, shake (s remaining, drives `fn_combat::prop_wobble` sway) }` (`PropInstance::from_world(&fn_combat::World)` for the live harvestables); `set_props(&[PropVertex])` is unchanged for pre-built geometry; `PropTemplates::build` expands without a renderer; `Renderer::prop_vertex_count()`. fn-render now depends on `fn-combat` (glam only). Call it every frame while something shakes (uploads ~0.3 MB for 50 props).
* **GPU timing**: `Gpu::new` requests `TIMESTAMP_QUERY` (+ `TIMESTAMP_QUERY_INSIDE_ENCODERS`) when the adapter has them; `Renderer` brackets `shadow cascade 0..2`, `sky`, `scene`, `hdr mip n`, `exposure`, `post`, `fxaa` with pass timestamp writes and the UI overlay with queue-ordered markers (needs INSIDE_ENCODERS). Results come back through an 8-deep staging ring without stalling and lag the CPU by 1-3 frames; if all 8 are in flight a frame is simply not measured. API: `last_pass_timings() -> &PassTimings { supported, frame, passes: Vec<GpuPassTime{name, group (shadow|sky|scene|post|ui), ms}>, span_ms }` (`group_ms`, `groups`, `sum_ms`), `gpu_timing_supported()`, and for benchmarks `flush_gpu_timings()` (blocks) + `take_pass_timings()` (all frames since last call). Without the feature everything is a no-op and `supported == false` (devices created elsewhere than `Gpu::new` must request the feature themselves).
* **fn-viewer**: `--gpu-timings [--frames n (default 300)] [--size WxH] [--demo-ui] [--prop-count n]` prints mean / p50 / p99 / max per pass and per group; `--prop-count n` scatters n extra trees/rocks (random yaw/scale, every 7th shaking); in the window `T` prints the last timings. `cargo test -p fn-viewer` includes `prop_shot` (needs GPU + `..\FortniteRuntime` assets/capture, skips otherwise): trees, trunk, rock, rock underside and tree shadow within 2 % luma of `idle.bmp`, no near-black growth.

## Device errors and size limits (additive, `gpu.rs`; fn-app: read this)
* `Gpu::new` still installs the strict handler (`on_uncaptured_error` -> `panic!`): right for tools and tests. **Applications call `Gpu::install_error_sink()`** (fn-app's `Gfx::new` does): it replaces the handler by one that logs `[wgpu error] ...` to stderr and records the message in the returned `Arc<GpuErrorSink>` (`take()` -> messages since the last call, at most 16 kept; `total()` counts all). The app polls it (`Gfx::acquire` returns `Acquire::Fatal("GPU error: ...")`), so a validation error ends in a clean exit 1 with a message instead of a panic / abort (exit 0xC0000409). Re-exported as `fn_render::GpuErrorSink`.
* `Gpu::max_texture_dimension_2d()` is the device limit (>= 8192 after `Gpu::new`); every surface / HDR target size must be clamped to it before `Surface::configure` (`fn-app/src/gfx.rs::clamp_surface_size`). A 9000 px wide window used to crash with "`Surface` width and height must be within the maximum supported texture size".

## Textured static meshes: the real 1.8 trees / rocks (task log, additive API)
Shaders: `static_common.wgsl` (instance + wind), `static_scene.wgsl`, `static_shadow.wgsl`; the lighting shared with `scene.wgsl` (camera/light blocks, cascade shadows, ambient, normal mapping, GGX, fog tail `output_hdr`) moved to `lit_common.wgsl` (no behaviour change). Rust: `static_mesh.rs` (CPU types, LOD / fade / frustum maths, mip builders), `statics.rs` (GPU), `static_loader.rs` (fn-propdata -> GPU), `synthetic.rs` (test tree / rock / checker quad).

**How fn-app replaces `set_prop_instances` with the real props**
```rust
// once, after Renderer::new (CPU decode of ~50 kinds takes ~2 s, do it on the loading screen):
let set = fn_render::static_loader::load_dir(&mut renderer, &assets.join("props"))?;   // Err / empty => keep the procedural path
// per frame (or when something changes; it only copies the list):
let inst: Vec<StaticMeshInstance> = world.props.iter().filter(|p| p.alive()).map(|p| {
    let kind = set.get(&p.real_id).unwrap_or(fallback);
    StaticMeshInstance::new(kind.mesh, p.pos).with_yaw(p.yaw).with_scale(p.scale).with_shake(p.shake)
}).collect();
renderer.set_static_instances(&inst);
renderer.set_prop_instances(&[]);            // and stop drawing the procedural trees / rocks
```
`StaticMeshInstance { mesh, pos, yaw, scale, shake, sway }`: `shake` is `Harvestable::shake` (the old `prop_wobble` x-sway, growing linearly with height), `sway` multiplies the material wind (0 = rigid). Keep the list order stable (LOD hysteresis state is per list index; a length change resets it). Missing assets: `load_dir` returns `Err` (no `catalog.json`) or a `PropSet` with `skipped` kinds; in that case simply keep calling `set_prop_instances` (the procedural path is untouched and still works; both can be drawn together). Other entry points: `create_static_material(&StaticMaterialData)`, `create_static_mesh(&StaticMeshData, &[StaticMaterialHandle])` (LOD list, sections, `cull_distance`, `cast_shadow`), `static_loader::load_catalog(renderer, &PropCatalog, filter)`, `static_stats() -> &StaticStats` (visible, LOD counts, culls, draw calls, triangles of the last frame), `static_instance_count()`.

**Pipeline**: one pipeline pair for the scene (cull back for one-sided, none for two-sided) and one for the shadow cascades (opaque = vertex only, masked = alpha-tested fragment). Per frame `prepare` culls every instance (distance cull + dithered distance fade over the last 10 % of `cull_distance`, bounding-sphere frustum test, LOD with +-10 % hysteresis, per-cascade light-box test that ignores the light depth range so casters outside the view still shadow it, shadow distance 45 m) and writes ONE instance buffer (48 B per instance: position/scale, yaw/fade/shake, wind phase/time/sway/1 over height) holding the main list and the 3 cascade lists grouped per (mesh, LOD); every group is one `draw_indexed(.., first_instance..first_instance + n)` per section, so draw calls scale with the number of distinct (mesh, LOD, section), not with the number of props. Foliage: base colour is `Rgba8UnormSrgb` with a CPU mip chain filtered in linear light, alpha-weighted (no colour bleed from transparent texels) and, for masked materials, the alpha of every mip rescaled to keep the level-0 coverage at the cutoff (so distant foliage keeps its density and the alpha test does not shimmer or thin; plain compare in the shader). Two-sided: the normal is flipped to face the viewer (independent of the exported winding), the shadow lookup is offset to the sun side so a leaf lit from behind does not shadow itself, back faces get transmitted light `albedo * sun * translucency` (ASSUMED 0.35). Shading = the prop path (sun x cascade visibility + sky hemisphere ambient with the ambient share in HDR alpha for AO, UE height fog) + optional normal map + GGX sun specular. The winding of real meshes is detected from the signed volume of the one-sided sections and flipped on load when needed.

**Velocity (fn-postfx)**: static meshes write NO velocity. Their motion is purely camera motion, which the post pass reconstructs from depth + the previous view-projection; shaking / swaying vertices (wind <= a few cm per frame, hit shake) are not written to the velocity target either. When a velocity target is added to the scene pass, static instances need no change except for foliage wind/shake, whose per-frame displacement could be output the same way (not done).

**Recovered vs ASSUMED**: recovered (`fn-propdata`): meshes + LOD `screen_size`, material blend mode / two-sided flag / clip value, textures and their sRGB flags, cull distance, cast-shadow flag, `SpecRoughnessMin/Max`, `LeafAnimationAmount`. ASSUMED: the LOD distance law `1.0605 * sphere_radius / screen_size` (UE 4.16 `ComputeBoundsScreenSize`, recalled), the wind model (gust along a fixed direction, quadratic height ramp, sway 3 % of height, leaf flutter = 0.6 x LeafAnimationAmount metres: the WPO node arithmetic of the 1.8 tree material is not recoverable), translucency, the opacity channel (R of the `MaskTexture`: verified on the pines), `Diffuse` / `Normals` / `MaskTexture` parameter names win over the exporter's slot heuristic (which picks `Branch Thicken Diffuse Map` for `MI_Pine_02_Ambient_Leaves`). Not done: subsurface colour (`SSS Color` is exported but unused), the damage/reveal textures, vertex-colour wind weights (flag exists: `wind_from_vertex_color`), alpha-to-coverage, LOD cross-fade (hysteresis only), a depth pre-pass.

**Tools / tests**: `fn-viewer --props <dir> --prop-grid N [--prop-kind Pine_3,Rock] [--prop-seed s]` (synthetic foliage tree + rock without `--props`; `--no-props` hides the procedural sandbox, which is also hidden automatically when statics are present), `--gpu-timings` now prints the static culling / draw-call line. `cargo test -p fn-viewer static_shot` (alpha test vs opaque control, two-sided front/back luma, one-sided back cull, leaf-shaped alpha-tested shadows, 500-tree batching = 4 draw calls, LOD hysteresis, distance + frustum culling, casters outside the view, the real exported props); `cargo test -p fn-render` (mips, coverage, LOD, fade, frustum, winding, loader maths). Both pass with `FN_VALIDATION=1` and `=2`. Screenshots: `reports\statics\*.png` (`real-*` real props, `syn-*` synthetic, `test-*` test captures).

### `static_loader::prepare_kind` / `upload_prepared` (added for fn-app's loading screen; `load_catalog` is unchanged and now calls both)
`prepare_kind(&PropKind, &known_materials) -> PreparedProp` is the CPU half of loading one kind (glTF LODs, material + PNG decode, LOD distances, winding detection) and needs no renderer, so it can run on worker threads while `Renderer::new_with_progress` compiles pipelines; `upload_prepared(&mut Renderer, PreparedProp, &mut cache) -> LoadedProp` creates the GPU materials (shared ones once, keyed by the `.mat.json` path in `cache`) and the mesh. `PreparedProp::texture_bytes()` reports the decoded texture size held. fn-app decodes on a bounded queue (6 kinds) and uploads kind by kind (one progress unit each), see `fn-app/README.md` "Real 1.8 props".


## Particle pass (task log, additive API)
`particles.rs` + `shaders/particles.wgsl`: camera facing / velocity aligned sprites with sub-UV sheets (`sub_image` fractional index, optional frame blend, pivot offset) and instanced mesh particles, drawn after the FX pass over the HDR target with the scene depth READ-ONLY (graph pass `particles`). Blend states are the same UE base-pass ones as `fx::FxBlend` (translucent `SrcAlpha, InvSrcAlpha` / alpha `Zero, InvSrcAlpha`, additive `One, One`, modulate `DestColor, Zero`); masked / opaque materials are alpha tested and drawn before the blended ones. The pass does not depend on the FX pass resources: it has its own textures (CPU box-filtered mips), materials, meshes and instance buffers.
API (all on `Renderer`): `create_particle_texture(w, h, rgba8, srgb, label)`, `create_particle_material(&ParticleMaterialDesc)` (blend, masked + clip, unlit, two sided, texture, opacity channel, value channel + 2 / 3 colour ramp, opacity exponent, emissive, tint), `create_particle_mesh(&ParticleMeshDesc)`, `set_particle_frame(ParticleFrame { sprites: Vec<SpriteBatch>, meshes: Vec<MeshBatch> })` once per rendered frame (batches are consumed by the frame; submit again for a second render of the same frame), `particle_stats()`. fn-app builds the frame from `fn-particles` (`fn-app/src/particles.rs`, `PARTICLE HOOK`). Shading: unlit = colour as emissive HDR; lit = sun + sky ambient on a camera facing normal (no cascade shadows) + height fog; the HDR alpha carries the ambient share for masked draws only.
