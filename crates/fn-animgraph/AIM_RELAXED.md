# Aim pitch on the held weapon + relaxed (lowered) weapon pose (1.8)

Evidence: the 1.8 `Fortnite_M_Avg_Player_AnimBlueprint` (bytecode dump, serialized node bytes of its `.uexp`), `CoreAnims_Male` (`reports/animation-state-machines.json`
`coreAnims`, values only), the AimOffset assets (`fn-inspect props`) and `FortniteClient-Win64-Shipping.exe` (static disassembly with `fn-exe-defaults scan`, never executed;
RVAs are image offsets, base 0x140000000). Nothing was tuned: every number below is read from the data or the exe unless it is under ASSUMED.

## Bug B: "I can't look up and down with the gun"

### What 1.8 does
* `AimPitch` (`FortAnimInstance` +0x3BC) and `AimYaw` (+0x3C0) are NATIVE: the Blueprint only reads them. They are written by `FortAnimInstance` RVA **0x40bd20**
  (writes `[this+0x3BC]` at 0x40bfc6 and `[this+0x3C0]` at 0x40c043); the fall-back path **0x40c090** (non-player pawns) stores `NormalizeAxis(pawn->vcall(+0x688).pitch)` into +0x3BC.
  Yaw is expressed relative to the actor (the direction vector is un-rotated by the actor quaternion before `FVector::Rotation`), pitch in world space, both wrapped to (-180, 180].
* BlueprintUpdateAnimation, bytecode **0x780e..0x7917**:
  `AdjustedAimPitch = (1 - GetCurveValue(ZeroOutPitchWeight)) * (AimPitch * 1 + SelectFloat(HACKAimPitchOffset(3.0), 4, AthenaAim))` (both `AimPitch<0` branches multiply by 1;
  `AthenaAim` is set true at 0x3c2c for an Athena pawn). Adjusted Aim Yaw: `(ActorYawOffset + AimYaw) * (sum<0 ? 0.9 : 0.8) + HACKAimYawOffset(-3)` (already ported).
  `UpperBodyAimOffsetAlpha` (0x772c..0x778d) = `(IsPlayingMeleeAnim || ShouldApplyAimOffsetToFullBody || IsSkydiving || isDBNO) ? 0 : 1`; `FullBodyAimOffsetAlpha` (0x779c..0x77ff) =
  `ShouldApplyAimOffsetToFullBody && !IsSkydiving && !isDBNO`. For the AR / shotgun / sniper `ShouldAimOffsetsApplytoFullBody` is false, so only the UPPER-body AO runs.
* The AO nodes are `RotationOffsetBlendSpace` #489 / 492 / 494 / 507 / 510 / 511 (+ the full-body #483): `X = Adjusted Aim Yaw`, `Y = AdjustedAimPitch` (bytecode 0x6680, 0x673f, 0x67d7, 0x6835,
  0x696f, 0x69de, 0x6a2b), asset = `AO_Targeted` / `AO_NonTargeted` / `AO_Relaxed` = `CoreAnims_Male[weapon].TargetingAimOffset / Non-targetingAimOffset / RelaxedAimOffset`
  (AssaultRifle: `AO_AR_NT_CMM`, `AO_AR_NT_CMM`, `M_NoWep_Relaxed_AO`), each sitting directly on its own pose pin of the PreUpperBodySlot BlendListByBool tree (below).
  The RotateRootBone pitch pair around the `MeshRotationUpperBody` slot (0x6afe `AimPitch * -1`, 0x6b2d `AimPitch`) is unchanged and cancels out.

### Root cause in the port
The pitch WAS fed (`PawnSample.camera_pitch_deg -> PawnInput.aim_pitch -> Vars.aim_pitch / adjusted_aim_pitch`, alphas correct: upper 1 / full 0) but
`ao_samples()` looks the blend space up with `blendspace(name)`, and the generated data (`anim_data.rs`, from `tools/animation-bs-evidence.cjs`) only contained
`M_Melee_TwoHanded_AO` (the pickaxe's). `AO_AR_NT_CMM`, `AO_Pistol_NT_CMM`, `M_GoingCommando_AO`, `M_Launcher_AO`, `M_NoWep_Relaxed_AO` did not exist, so `ao_samples` returned `[]`
and `upper_pre_slot` silently emitted no `AimOffset` node: no camera-pitch dependence at all (only the unrelated RotateRoot pair).

### Fix
* `src/anim_ao.rs` (new, GENERATED by ``cargo run -p fn-inspect --bin gen-anim-ao` (crates/fn-inspect/src/bin/gen-anim-ao.rs)` from `fn-inspect props`: BlendParameters, SampleData, GridSamples of the five CoreAnims aim offsets), `ALL_AIM_OFFSETS`;
  `blendspace()` searches it; `required_clips()` now also asks for their sample clips (all present in the store, `MeshSpaceRotationOffset`, 266 tracked bones).
* `upper_pre_slot` rebuilt as the real node tree (see Relaxed below), so every pin carries its own AO.
* Unit tests: `core_aim_offsets_exist_and_the_pitch_axis_selects_up_and_down_samples`, `held_weapon_pose_tree_follows_aim_pitch_through_the_aim_offset`.

### Measured (fn-app test `aim_pitch`, real 1.8 clips, AR held, gun barrel pitch in character space, degrees; camera pitch -60 / 0 / +60)
| state | before | after |
|---|---|---|
| hip (non-targeting) | 1.07 / 1.07 / 1.07 | **-56.69 / 2.93 / 63.99** (spread 120.7) |
| ADS (targeting) | 1.06 / 1.06 / 1.06 | **-56.70 / 2.92 / 63.99** (spread 120.7) |
| relaxed (after 6 s idle) | n/a (never relaxed) | -16.38 / -16.38 / -16.38 (see below) |

Relaxed note (data, not a bug): `M_NoWep_Relaxed_AO_*` keys only pelvis / spine_01..02 / clavicle_r / neck_01 / head (upperarm_r, hand_r and the IK bones have no track), so in 1.8 the lowered
rifle does not follow the camera pitch; only the head does. The barrel then sits 19 deg below the hip pose (-16.4 vs +2.9 pitch, yaw -45).

## Bug A: "the gun never goes down"

### What 1.8 does
`bIsRelaxedLevel1`, `bIsRelaxedLevel2`, `bRecentlyFired` are NATIVE `FortAnimInstance` properties (`/Script/FortniteGame.FortAnimInstance`, registered in the ZConstruct at RVA 0xe11630; the
AnimBP only reads them: no `letbool V:bIsRelaxedLevel*` anywhere in its bytecode). The AnimBP derives `TempIsRelaxedLevel1 = bIsRelaxedLevel1 || RightArmMaskWeight > 0`
(0x6fc5..0x6fdb, already ported) and `TargetingToNonTargBlendTime = SelectFloat(0.06, 0.4, IsMontagePlaying)` (0x7926).

Offsets (reflection registration, RVA 0xe11630): `bRecentlyFired` +0x3D0, `bIsRelaxedLevel1` +0x3D1, `bIsRelaxedLevel2` +0x3D2 (bool order = registration order, confirmed by the code below),
`TimeForRecentlyFired` +0x3C4, `TimeToReachRelaxedLevel1` +0x3C8, `TimeToReachRelaxedLevel2` +0x3CC, `RelaxedLevelTimeCounter` +0x3D4, `SavedWeaponLastFireTime` +0x3D8.
Defaults (class ctor RVA **0x3ce020**; the AnimBP CDO does not override them): **0.2 s, 5.0 s, 15.0 s** (immediates 0x3E4CCCCD, 0x40A00000, 0x41700000).

The rule is the function at RVA **0x40efb0** `(this, APawn* pawn, float dt)`, called from the per-tick native update **0x40e100** (right before `BlueprintUpdateAnimation`):
```
weapon = pawn->CurrentWeapon (+0x830, AFortPawn); if (!weapon) return;
last   = weapon->LastFireTime (+0x954)
if (last == SavedWeaponLastFireTime && !weapon->bIsReloadingWeapon(+0x3A1) && !weapon->bIsChargingWeapon(+0x3A2)) {
    if (weapon->bIsEquippingWeapon(+0x3A0)) RelaxedLevelTimeCounter = TimeToReachRelaxedLevel1;
    else                                    RelaxedLevelTimeCounter += dt;
} else { SavedWeaponLastFireTime = last; RelaxedLevelTimeCounter = 0; }
bRecentlyFired   = !((World->TimeSeconds(+0x900) - SavedWeaponLastFireTime) > TimeForRecentlyFired);
bIsRelaxedLevel1 = RelaxedLevelTimeCounter >= TimeToReachRelaxedLevel1;
bIsRelaxedLevel2 = RelaxedLevelTimeCounter >= TimeToReachRelaxedLevel2;
```
(the three `AFortWeapon` bools are the last three registered properties of the weapon ZConstruct RVA 0x11fc5c0: `bIsChargingWeapon`, `bIsReloadingWeapon`, `bIsEquippingWeapon`).
What resets it: a shot (LastFireTime is stamped at the fire notification 0x921cf0, in the fire path 0x941d60 and by the vtable-+0x918 function 0x944900 that the weapon runs right after
`Fire` (+0x940), e.g. at 0x5def30), a reload, a charge, or switching to a weapon with a different LastFireTime. Equipping pins the counter at 5 s, i.e. a freshly equipped weapon is
relaxed level 1 immediately and level 2 after 10 more seconds. NOT in the rule: targeting (`SetTargeting` 0x93ade0 only writes `bIsTargeting` and `LastTargetingTransitionTime`; the AnimBP
just gives the `bIsTargeting` pin priority), damage, sprinting, jumping.
`LastFireTime` is initialised to -10 (weapon ctor 0x914b60).

PreUpperBodySlot BlendListByBool tree (node ids of `animation-graph-nodes.json`, pin 0 = true). BlendTimes were read from the serialized node bytes in the AnimBP `.uexp`
(the report drops them): standing: 505(IsCrouching, 0.2) -> 490 `bIsTargeting` [0.1 into targeting, **TargetingToNonTargBlendTime** (Array_Set at 0x6774) into the other pin] ->
491 `TempIsRelaxedLevel1` [**0.4** into relaxed, **0.05** out of it] -> 492 (`AO_Relaxed` over) 493 `bIsRelaxedLevel2` [**0.4** into Level2 pose, **0** into the Level1 pose]; crouched:
506 `bIsTargeting` [0.1, TargetingToNonTargBlendTime] -> 509 `TempIsRelaxedLevel1` [0.4, 0.05] (single `CrouchUpperBodyPose_Relaxed`, no Level2 node).

### Root cause in the port
`Vars.b_is_relaxed_level1/2` were never assigned (and `PawnInput.recently_fired` was never set by the game), so `temp_is_relaxed_level1` was always false and the graph could never reach
`RelaxedPose / RelaxedAimOffset / RelaxedPose2`. The pose pins were also switched instantly (no BlendListByBool timing).

### Fix
* `graph.rs`: constants `TIME_FOR_RECENTLY_FIRED / TIME_TO_REACH_RELAXED_LEVEL1/2`, `WeaponClock`, `Vars::update_relaxed` (the function above, same operation order), called from `Vars::update`
  before the EventGraph part; `AnimState::set_weapon_clock`; `bRecentlyFired` now comes from the same function (it also gates the sprint state machine in the AnimBP).
* `graph.rs` `upper_pre_slot`: real BlendListByBool tree with the serialized BlendTimes (`up_targeting`, `up_targeting_c`, `up_relaxed`, `up_relaxed_c`, `up_relaxed2`; same `BlendList` helper as the
  other ported lists), per-pin pose + per-pin AO. `slot()`, the RotateRoot chain, CopyBone / hand IK, SlotBlend, CurveBlend, the jump machine, recoil, movement: untouched.
* `fn-game/sim.rs`: `GameSim::set_weapon_clock`. `fn-app/arms.rs`: `last_fire[g]` (init -10, stamped with the arms clock on each shot) and `Arms::weapon_clock()`
  (`reloading` = reload act, `equipping` = equip act). `fn-app/app.rs`: `sim.set_weapon_clock(arms.weapon_clock())` next to `set_held`.

### ASSUMED (not provable from data / exe, labelled in code)
* `AimPitch` / `AimYaw` values: 0x40bd20 builds them from two native virtual calls (pawn vtable +0x680 and an object at +0x1958 vtable +0x5B8) that were not decoded; the port feeds the camera
  (control-rotation) pitch and its yaw relative to the actor, as before. Parallax between the third-person camera and the muzzle is therefore not modelled.
* `bIsEquippingWeapon` window = the equip montage window (`Act::Equip`); `bIsChargingWeapon` always false (no charge weapon in the starter loadout).
* The pickaxe / consumables have no `WeaponClock`: never relaxed (the pickaxe has no relaxed pose / AO in `CoreAnims_Male[Melee]`); putting the rifle away clears the counters.
* `Montage_IsPlaying(null)` is never true in UE 4.16 (compares the instance's montage with null), so `TargetingToNonTargBlendTime` = 0.4 s.
* Who else calls the +0x918 LastFireTime stamp besides the post-fire call (pawn init paths at 0x4397c0, 0x47bed0, 0x633620 ...) is not simulated.
* BlendListByBool alpha shape = the existing `BlendList` helper (linear, restart from the current weights); `CustomBlendCurve` is null in all nodes.
* Still not modelled (pre-existing, LAYERED.md): `JogAdditiveBlendspaceRelaxed*` spaces, so a relaxed jog uses the same additive as the hip jog; the Pistol left-arm rule `bIsRelaxedLevel2` is now live but there is no pistol in the loadout.

### Tests (all run once at the end; results at the bottom)
* fn-animgraph: `native_relaxed_rule_matches_the_1_8_function` (5 s / 15 s thresholds, shot reset + 0.2 s window, reload / charge hold at 0, equip pins at 5 s),
  `rifle_relaxes_after_five_seconds_and_firing_or_targeting_cancels_it` (end to end through the pose tree: hip pose < 5 s, `M_AssaultRifle_Relaxed` + `M_NoWep_Relaxed_AO` after 5 s with a 0.4 s blend,
  a shot restores `M_AssaultRifle_NonTargeted` within 0.05 s, ADS shows `M_AssaultRifle_Targeted` and leaves the timer running), the two AO tests above.
* fn-game: `weapon_clock_drives_the_relaxed_pose_and_a_shot_cancels_it` (4.5 s ready, 5.5 s relaxed, shot cancels, 15 s level 2, pickaxe clears).
* fn-app: `arms::tests::weapon_clock_reports_last_fire_time_reload_and_equip`, `aim_pitch::aim_pitch` (real 1.8 assets, the table above, asserts spread > 90 deg hip and ADS, relaxed constant and lowered).

Results: `cargo test --release -p fn-animgraph -p fn-game`: 57 passed (fn-animgraph) + 102 passed (fn-game), 0 failed. `cargo test --release -p fn-app aim_pitch` and `arms`: pass (26 arms tests).
`cargo build --release -p fn-app`: finished. CARGO_TARGET_DIR D:\target-relaxaim; nothing copied into dist; the Fortnite client was never run.
